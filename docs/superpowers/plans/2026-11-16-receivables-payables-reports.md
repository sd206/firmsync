# Receivables and Payables Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two new reports under Reports — Receivables (who owes us, how overdue, how slowly they pay) and Payables (what we owe vendors, what is due soon, what awaits approval) — each with a summary, a drill-down and CSV downloads.

**Architecture:** One migration adds four security-definer report functions (summary + detail for each side) that take today's date from the app. Two TS modules (`src/modules/reports/receivables.ts`, `payables.ts`) parse URL params, call the functions, total the rows and build CSVs. Two server pages and two CSV routes mirror `reports/transactions`.

**Tech Stack:** Next.js 15 (App Router, server components), Supabase Postgres (plpgsql), vitest (unit + integration projects), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-receivables-payables-reports-design.md`

## Global Constraints

- Admins and managers only: every function checks `public.has_role(p_firm, '{admin,manager}'::public.firm_role[])`, else `raise exception 'permission denied' using errcode = '42501'`; pages/routes use `requireFirmRole(firmId, ['admin', 'manager'])`.
- Functions: `language plpgsql stable security definer set search_path = ''`; `revoke execute ... from public, anon; grant execute ... to authenticated`.
- Money leaves SQL as `numeric(12,2)::text`; the UI formats with `formatMoney(v, firm.currency)`; CSV amounts are plain numbers (`csvField(v, { text: false })`), text cells `csvField(v, { text: true })`, BOM + CRLF like `buildTxnCsv`.
- Balances are as of `p_today` (passed as `todayIso()` from the app). No past "as of" option.
- Buckets reuse `AgeBucket` / `AGE_BUCKET_LABELS` from `src/lib/domain/ageing.ts`: days overdue = `p_today - due_date`; `<=0` current, `1–30`, `31–60`, `61–90`, `>90`.
- Receivables owed = invoices with status `issued` or `partly_paid`; balance = `total - amount_paid`.
- Payables owed = vendor bills `approved` or `partly_paid`, balance = `total - amount_paid`. `pending_approval` bills are reported separately (amount = `total - amount_paid`) and never added to Total owed. `rejected`, `void`, `paid` excluded.
- Payables not-yet-due split by days until due (`due_date - p_today`): `0–7` → "Due in 7 days", `8–30` → "Due in 8–30 days", `>30` → "Due later".
- Days-to-pay history: invoices with status `paid` whose paid date (= `max(payments.paid_on)` for the invoice) is in `(p_today - 365, p_today]`. Avg days to pay = avg(paid date − issue_date); avg days late = avg(greatest(paid date − due_date, 0)); one decimal; null when none.
- "Overdue only" filters invoices/bills to `p_today - due_date > 0` before aggregation (both sides; on payables it applies to awaiting-approval bills too).
- Clients/vendors with nothing open (after filters) are not in the summary.
- Copy: menu labels **Receivables**, **Payables**; buttons **Download summary (CSV)**, **Download invoices (CSV)** / **Download bills (CSV)**.

## Review Focus

1. A partly paid invoice/bill — the aged amount must be the remaining balance, not the total (pinned in Task 1 tests).
2. An invoice due exactly today and a bill due exactly today / in exactly 7 and 8 days — boundary buckets (pinned in Task 1 tests).
3. A client whose only paid invoice was paid in several instalments — paid date is the last instalment (pinned in Task 1 tests).
4. Another firm's ids in `clients=`/`vendors=` params, or a consultant calling the functions — must return nothing / 42501 (pinned in Task 1 tests).
5. Garbage URL params (`clients=not-a-uuid`, `client=xyz`) — ignored, never a 500 (pinned in Task 2/3 unit tests).

**Interfaces:**
- Produces (all `returns table`, rows as below; money columns `text`, day counts `integer`, averages `text` like `'12.5'` or null):
  - `receivables_report(p_firm uuid, p_today date, p_clients uuid[], p_overdue_only boolean)` → `client_id uuid, client_name text, not_due, d1_30, d31_60, d61_90, d90_plus, total text, oldest_overdue_days integer (0 when none overdue), open_invoices integer, avg_days_to_pay text, avg_days_late text` — order by (`d1_30+…+d90_plus`) desc, then `client_name`.
  - `receivables_invoices(p_firm uuid, p_today date, p_clients uuid[], p_overdue_only boolean)` → `invoice_id uuid, number text, client_id uuid, client_name text, issue_date date, due_date date, total, amount_paid, balance text, days_overdue integer` — order by `client_name, due_date, number`.
  - `payables_report(p_firm uuid, p_today date, p_vendors uuid[], p_overdue_only boolean)` → `vendor_id uuid, vendor_name text, due_7, due_8_30, due_later, d1_30, d31_60, d61_90, d90_plus, total, awaiting_approval text, awaiting_count integer, oldest_overdue_days integer` — order by overdue sum desc, `due_7` desc, `vendor_name`.
  - `payables_bills(p_firm uuid, p_today date, p_vendors uuid[], p_overdue_only boolean)` → `bill_id uuid, bill_number text, vendor_id uuid, vendor_name text, status text, bill_date date, due_date date, total, amount_paid, balance text, days_overdue integer` — approved/partly_paid/pending_approval only; order by `vendor_name, due_date, bill_number`.
  - `p_clients` / `p_vendors` null = all. Payables `oldest_overdue_days` counts approved/partly_paid bills only.

**Interfaces:**
- Consumes: Task 1 `receivables_report`, `receivables_invoices`.
- Produces:
  - `sumMoney(values: string[]): string` — exact decimal sum to 2 places via integer cents (e.g. `['0.10','0.20'] → '0.30'`, `[] → '0.00'`, negatives allowed).
  - `type AgeingParams = { ids: string[]; overdueOnly: boolean; focus: string | null }`
  - `parseAgeingParams(search: Record<string, string | string[] | undefined>, listKey: 'clients' | 'vendors', focusKey: 'client' | 'vendor'): AgeingParams` — `ids` = every value of `listKey` (repeated or comma-separated) that matches the UUID regex, de-duplicated; `overdueOnly` = `search.overdue === '1'`; `focus` = `focusKey` value if a UUID, else null. Never fails.
  - `ageingQuery(p: AgeingParams, listKey, focusKey): URLSearchParams` — inverse, for CSV links.
  - `type ReceivableRow = { clientId; clientName; notDue; d1_30; d31_60; d61_90; d90Plus; total: string; oldestOverdueDays: number; openInvoices: number; avgDaysToPay: string | null; avgDaysLate: string | null }`
  - `type ReceivableTotals = { total; overdue; over60: string; overdueClients: number; notDue; d1_30; d31_60; d61_90; d90Plus: string; openInvoices: number }` (over60 = d61_90 + d90Plus).
  - `type OpenInvoiceRow = { invoiceId; number; clientId; clientName; issueDate; dueDate; total; amountPaid; balance: string; daysOverdue: number }`
  - `getReceivables(db, firmId, today: string, p: AgeingParams): Promise<Result<{ rows: ReceivableRow[]; totals: ReceivableTotals }>>`
  - `getOpenInvoices(db, firmId, today: string, p: AgeingParams): Promise<Result<OpenInvoiceRow[]>>` — when `p.focus` is set, passes `[p.focus]` instead of `p.ids`.
  - `receivableTotals(rows: ReceivableRow[]): ReceivableTotals` (pure, exported for tests).
  - `buildReceivablesSummaryCsv(rows, totals, today): { filename: \`receivables-summary-${today}.csv\`; body }` — header `Client,Not yet due,1–30 days,31–60 days,61–90 days,Over 90 days,Total owed,Oldest overdue (days),Avg days to pay,Avg days late,Open invoices`, then a `Total` row.
  - `buildOpenInvoicesCsv(rows, today): { filename: \`receivables-invoices-${today}.csv\`; body }` — header `Client,Invoice,Issue date,Due date,Total,Paid,Balance,Days overdue`.
